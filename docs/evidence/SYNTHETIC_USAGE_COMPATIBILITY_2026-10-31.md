## Why the implementation changes

The domain contract intentionally accepts only inputTokens/outputTokens/totalTokens.
That is an **internal normalized contract**, not a statement that the external API
can never add response metadata. The existing SDK transport already projects
those three members. A new no-network test supplied additional metadata to the
pinned SDK deserializer: the SDK discarded it, whereas our native normalizer
rejected the otherwise identical usage. That regression failed before correction.

The native normalizer now performs the same explicit three-member projection.
Unmodeled response members are not copied into usage, diagnostics or browser
content. Known cache counters/details are still checked for inactive values;
required token fields are not defaulted or repaired. Domain sum, finite/integer,
input/output caps and tool-result checks remain unchanged. The bounded JSON parser,
TLS/signing, fixed payload, no-cache request, request count, deadline and IAM policy
are unchanged. This is response compatibility, not permission to ignore invalid
required counters, enable caching, repair arbitrary model text or retry a call.

The focused suite passed **37 tests** and service typecheck. New tests verify SDK
parity, no extra metadata in normalized usage/snapshots, no mutation of the raw
fixture, invalid required fields still rejected by the domain, active cache usage
still rejected, one STS assumption and unchanged one/two-request control flow.
