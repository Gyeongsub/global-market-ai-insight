## プロジェクトの概要

市場情報を調べるための質問を作成する多言語ローカルツールと、合成データを実際の
Amazon Bedrockで分析する本人専用の実習機能を実装したプロジェクトです。最小権限、
時間制限、コスト制御、検証後のリソース削除までを一連の運用として設計しました。

## 当初の課題とスコープ変更

当初は、外部の株価API、イベント駆動のAWS処理、AI分析を一つのサービスとして
接続する計画でした。実装だけでなく、データの取得、画面表示、AIへの入力、再配布に
関する権利、登録時の個人情報提供、呼び出し回数と課金条件を個別に確認する必要がありました。

個人学習という目的を維持し、不確かな契約や追加登録を避けるため、機能を分離しました。
最新情報の調査は、利用者が既存のChatGPT画面で直接行います。AWSの学習では、
合成データであることを明示した固定のQLDデータを使用します。架空の値を実際の株価として
表示したり、データ利用許諾の問題が解決済みであると説明したりはしません。

## 現在利用できる二つの経路

| 経路 | 利用者の操作 | AWSとコストの境界 |
| --- | --- | --- |
| 検索質問の作成支援 | 銘柄・言語・質問の種類を選択 → 手動でコピー・送信 → ChatGPTで回答を確認 | アプリからAWSや検索APIへの呼び出しは発生しない。ChatGPTの利用条件と上限は別扱い |
| 実環境での合成データ分析実習 | 検証済みの一時中継プロセスを起動 → ブラウザーで1回分析 → 結果確認 → 終了 | モデル専用の一時ロールで東京リージョンのNova Liteを呼び出す。再試行なし、出力上限512トークン、認可期間は最大5分 |

従来のAPI Gateway、Lambda、DynamoDB、ECS、Fargateのコードは、別の学習用構成として
保存しています。現在のブラウザー分析が、この非同期経路全体を通るわけではありません。
従来構成では、データ提供元への処理と表示を無効にし、circuitをOPENに維持する運用方針です。
実際の状態確認は各検証記録の時点に限られるため、新たな実行の前に再確認します。

## AWSが担う役割

現在の製品におけるAWSは、検索エンジンやWebホスティングではなく、**制限付きの実際の
AI分析と最小権限運用を学ぶ実行環境**です。質問の生成はPC内で完結し、合成分析の実習を
明示的に開始して分析を要求した場合にのみ、Bedrockへリクエストを送ります。

```text
検索質問の作成支援
  ローカル画面 → 質問をコピー → 利用者がChatGPTへ送信 → ChatGPTで確認

実際のAWSによる合成データ分析
  所有者の認証 → 一時的なモデル専用ロール → 短期STS認証情報
                                          （ブラウザーには渡さない）
  ローカル画面 → 制限付き中継 → Bedrock Nova Lite → 結果検証 → 画面表示
                       ↓
  セッション終了 → 認証情報の破棄 → ロールとスタックの削除確認
```

| 構成要素 | このプロジェクトでの役割 | 採用しなかった代替案と理由 |
| --- | --- | --- |
| ローカル画面と中継プロセス | 本人のPC上で要求と結果を表示し、AWS認証情報はサーバー側だけに保持 | 公開Webホスティングではドメイン・認証・運用の範囲が増えるため、現在の目的から除外 |
| IAMロールとSTS | 分析に必要な限定的な権限を短期間だけ付与 | 管理者の認証情報をブラウザーや分析SDKへ渡さない |
| Amazon Bedrock | 固定の合成資料に基づき、限定された分析項目を選択 | 新たな株価APIへの登録や実際の金融データの利用権を必要としない実習 |
| AWS CDKとCloudFormation | 一時ロールと保存済みの学習構成をコードで定義・管理 | コンソールでの手動変更だけを積み重ねるより、変更と削除の手順を追跡しやすい |
| API Gateway・Lambda・DynamoDB・Fargate | 過去の非同期ジョブ、重複防止、状態遷移の学習コードを保存 | 現在の直接Bedrock経路に必須の実行要素とは説明しない |

保存済みの構成では、DynamoDBがジョブの状態と条件付き遷移を管理し、Fargateがジョブ単位で
コンテナーを実行します。常駐サービスを維持する方式とは異なります。ただし、現在の分析ボタンが
この構成を実行するわけではありません。

## 設計から得られた学び

1. **認証と認可の分離：** 所有者のCLIログインはインフラ管理に使い、分析SDKには別の
   モデル専用STS認証情報を渡します。ブラウザーにAWSキーはありません。
2. **制御範囲の明示：** STS認証情報の有効期間15分、セッションポリシーによる絶対時刻での
   許可期間5分、アプリのモデル試行1回は、異なる制御です。再起動すると新たな利用枠になります。
3. **成功だけでなく拒否も検証：** 許可されたモデル呼び出し、期限後の明示的な拒否、別ロールの
   アクセス拒否、ECS実行の拒否を、それぞれ限定した試験で確認しました。全権限の網羅的な検証を
   意味するものではありません。
4. **モデル出力も信頼しない：** 固定の根拠から許可済みのインサイトIDだけを選ばせます。
   スキーマ、使用トークン数、必須のリスク表現を検証し、アプリが各言語の文章を表示します。
5. **終了処理も機能の一部：** 画面のCLOSED状態、ローカルリスナーの停止、認証情報の破棄、
   一時ロール・スタックの削除、独立した照会による残存確認を別々の条件として扱いました。

## セキュリティとコストの制御

分析を1回に制限する目的は、出力品質だけでなく、意図しない繰り返し呼び出しの防止です。
失敗も回数に含め、SDKの再試行を無効にしています。出力トークン上限は応答サイズの制限であり、
入力、他サービス、新規セッションの費用まで止めるアカウント全体の支出上限ではありません。

| 制御 | 防止したい問題 | 残る限界 |
| --- | --- | --- |
| 127.0.0.1限定アクセスと要求検証 | LANへの公開、意図しないブラウザー要求 | マルウェアが動作するPC自体を安全にするものではない |
| モデル・リージョン・合成入力の固定 | 別モデルの使用、機微な自由入力の送信 | 機能は限定的で、汎用的な投資分析サービスではない |
| モデル専用ロール | 分析プロセスによる秘密情報の取得やコンピューティング実行の制限 | 所有者の別の管理用認証には他の権限があり得る |
| 認可5分・STS15分・アプリ試行1回 | 長時間利用、繰り返し呼び出し | ロール削除だけで発行済み全セッションが即時失効するとは限らない |
| 検証済み項目IDと各言語の定型文 | 任意のモデル文章やHTMLをそのまま表示するリスク | 限定的な合成事例の結果であり、事実性全般の保証ではない |
| 終了後の独立した照会 | 削除コマンドの成功表示だけに依存すること | 確認対象外のリソースや遅延請求まで解消された保証ではない |

月額USD 5の予算通知は超過を知らせる仕組みであり、強制停止装置ではありません。
実習を実行しなくても、保存中のS3、ECR、DynamoDB、ログなどに費用が発生する場合があります。
目標は「常に無料」ではなく、**実行範囲と残存コストを説明し、終了を検証できる運用**です。

## 問題解決の事例

**市場データの利用条件：** API接続の成功と、データを表示したりAIへ入力したりする権利は
別問題でした。無料の代替サービスへの登録を増やすのではなく、実情報は利用者のChatGPT画面で
確認し、AWSには合成入力を送る構成に分離しました。技術的な接続より先に、要件と運用上の制約を
整理した判断です。

**モデル呼び出しと応答処理：** 実際の要求失敗に対して、ローカルでの互換性確認と限定的な
再検証を行いました。成功応答の使用量、更新後の要求回数、許可期間後の拒否を個別に確認しています。
正常要求が1回成功しただけで、IAMポリシー全体の完全な安全性が証明されるわけではありません。
[互換性修正と期限切れ検証](evidence/SYNTHETIC_USAGE_COMPATIBILITY_2026-10-31.md)を参照してください。

**開発依存関係のセキュリティ勧告：** 10月31日の照会では、開発用minimatchの二つのバージョンに
中程度の勧告1件が一致しました。宣言済みの実行時依存関係への一致は0件でしたが、「脆弱性なし」とは
表現していません。lint入力の固定、時間・メモリ制限は緩和策であり、パッチではありません。
その後11月1日に、10.2.6の両モジュール形式へ公式修正に基づく互換パッチを適用しました。
全ローカル検証は90段階、1,905件成功、既存のスキップ1件でした。元のバージョン範囲に対する
勧告と、実装が異なる3.1.5のレビューは残しています。公開用コピーの独立再現と最終的な
リリースリスク判断は別の確認事項です。
[パッチと検証記録](evidence/MINIMATCH_BACKPORT_2026-11-01.md)、
[勧告のレビュー](evidence/LINT_ADVISORY_REVIEW_2026-10-31.md)を参照してください。

## 実績として過大に表現しない範囲

リアルタイム株価サービス、投資助言サービス、公開利用者向け認証システム、無条件の支出上限、
あらゆる障害時の即時課金停止を実装したとは主張しません。新しい最小権限経路の実環境検証は
英語1回であり、それ以前の他言語の試験とは区別します。リモートCIは構成していません。
公開ソース候補の個人情報・権利・単一初期履歴のレビューと、再取得したファイルの一致確認は
完了していますが、コンテナーやビルド成果物の配布に関するライセンス・セキュリティ審査、
過去の全AWS実験まで完了したという意味ではありません。

AIの支援を受けて実装・検証したプロジェクトです。本人が直接行った操作と、AIによる実装を
区別し、まだ本人が実施していない実習を実務経験として記載しません。
[韓国語の学習ガイド](API_INTEGRATION_LEARNING_GUIDE_KO.md)にあるコード追跡や説明問題を使い、
構成と運用判断を自分で理解しているかを確認できます。

## 読み進め方と公開後の実習

実習は公開完了後に進めます。読むだけでは運用習熟の証明にはなりませんが、設計理由とコードを
結び付けることで、操作の目的を理解できます。最初の読解にAWSログインや有料モデル呼び出しは不要です。

1. [現在の計画](../plan.md)で、二つの有効な経路と保存済みの学習経路を区別します。
2. [アーキテクチャ](architecture.md)で、要求・データ・認証がどこへ移動するかを説明します。
   ブラウザーにAWSキーを渡さない理由を確認します。
3. [韓国語のAPI・AWSガイド](API_INTEGRATION_LEARNING_GUIDE_KO.md)で、過去のAPI連携と
   現在の合成実習の違い、IAM・STS・コスト制御の関係を理解します。
4. [合成実習の運用手順](runbooks/synthetic-bedrock-lab.md)で、まず開始条件と終了条件を読みます。
   実行は、その時点の認証・費用・安全条件を確認してから行います。
5. [検証結果一覧](PRIVATE_PORTFOLIO_STATUS.md)で成功・拒否・失敗・未検証を区別し、
   自分で再現して初めて本人の実習経験として記録します。

### 説明できるようにしておきたい質問

- 公開サーバーではなくローカル中継を選んだ理由と、その代わりに見送ったものは何か。
- 一時認証情報の有効期間、権限の許可期間、アプリの呼び出し回数はどう違うか。
- 現在の分析ボタンの実行経路にFargateが含まれない理由は何か。
- 通知が届く前にもコストを抑えるには、どの箇所で何を制限すべきか。
- 成功応答以外に、どのような拒否・終了の記録があれば安全な実習として説明できるか。

これらは公開前に所有者へ要求する課題ではなく、公開後の自主学習と面接説明のためのチェックリストです。
リンク先の補足資料は既存の言語のままであり、この日本語版は全資料の翻訳を意味しません。

## 5分間で説明する順序

1. 追加登録、市場データの利用権、費用を理由に機能を分離した経緯を説明します。
2. 検索画面で質問と出典に関する要求を示します。自動送信は行いません。
3. 既存の記録やスクリーンショットで、実際のAWS分析と最小権限経路を説明します。
   デモのたびに新しい有料呼び出しを行う必要はありません。
4. 拒否試験と終了の記録を示し、通知・権限・回数・有効期間の制御の違いを説明します。
5. 完成した範囲と[保留中の拡張・実習](PRIVATE_PORTFOLIO_STATUS.md)を明確に区別します。
